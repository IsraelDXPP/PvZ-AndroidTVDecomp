# Decisions

Decisions already taken, with the reason. Do not re-open them without new
data: if you think one is wrong, bring the measurement that shows it.

## D1. The oracle is the v115 build of `libGameMain.so`

**Decision.** Every function, field, constant and address in this port comes
from `app/src/v115/jniLibs/armeabi-v7a/libGameMain.so` in the AndroidTV
project.

**Reason.** The upstream decompiled the v115 build and the addresses in the
code are v115 addresses. The w111 build has the same functions at other
addresses, and the Hex-Rays exports on this machine are w111, so an export
can never be used to fix an address.

**Do not re-open without** a measurement that shows the v115 build is not the
one the code follows.

## D2. The platform layer is SDL3 and bgfx

**Decision.** The original `Win32AppDriver`, `Win32File`, `Win32Gamepad`, the
JNI entry point and the Java activity are gone. SDL3 provides windows,
events, gamepads, audio streams, threads, mutexes, clocks and file access;
bgfx provides rendering over Direct3D 11/12, OpenGL, Vulkan and Metal. The
entry point is `SDL_MAIN_USE_CALLBACKS`.

**Reason.** The goal is a native, cross-platform build (Windows, macOS,
Linux, Android, iOS) from a single codebase, and the original platform layer
was a JNI bridge to an Android activity. The driver interface stayed a plain
C++ virtual interface, so the game code did not have to change.

**Do not re-open without** a platform that SDL3 does not cover.

## D3. The TV layout and wave data are the default

**Decision.** The TV camera, the TV seed bank and the TV wave data are the
default. The PC-style low camera, the larger PC seed bank and the classic
level spawns are opt-in (`LAWN_LOW_VIEW`, `Levels/levels.pc.xml`).

**Reason.** This is a decompilation of the TV build. PC-style options are a
convenience, and they are behind `setup.env` so that the default stays the
one the binary describes.

**Do not re-open without** a reason to change what the default is.

## D4. The logical canvas is 720 pixels high

**Decision.** The canvas keeps a fixed height of 720 and a width taken from
the window aspect ratio: 960x720 at 4:3, 1280x720 at 16:9, 1680x720 at
21:9. The original 1280x720 region stays centred; wider windows reveal more
on the sides, narrower ones crop them.

**Reason.** The assets keep their original drawing coordinates, so the canvas
has to keep the original scale. A fixed height with a variable width is what
lets one asset set work on every aspect ratio.

## D5. MIT for the port, GPL-3.0-or-later for the adapted console content

**Decision.** The decompiled code is MIT. The console content and part of the
mouse controls, adapted from
[PlantsVsZombies-AndroidTV](https://github.com/ZombieYetis/PlantsVsZombies-AndroidTV),
keep the GPL header and are covered by
`ThirdParty/PvZTVTouch/NOTICE.md`.

**Reason.** The two parts have different origins and different licences, and
the combination has to be distributable. The adapted files keep their header
so the provenance is visible in the file.

**Do not re-open without** a licensing change upstream.

## D6. The upstream is merged by a pull request, never pushed directly

**Decision.** `.github/workflows/sync-upstream.yml` merges the upstream into
`upstream-sync` and opens a pull request into `main`. On conflict it
publishes `upstream-mirror` and opens an issue.

**Reason.** The fork's own commits must never disappear in a silent merge.
A pull request keeps the review in the hands of a person.

**Consequence.** The tree has to stay mergeable: additive changes, no
reformatting of files nobody is fixing.

## D7. The upstream's file layout is kept

**Decision.** One class per file, headers in `Lawn/include/game`,
`Sexy/include` and `TodLib/include`, bodies in the matching `src`
directory. The class names are the binary's.

**Reason.** The upstream owns the porting effort and the sync merges their
files. A different layout would make every upstream commit a conflict.

## D8. Machine-transcribed files are not hand-edited

**Decision.** The 46 sources and three headers marked
`Generated by tools/ida_transcribe.py. Do not edit.`, plus
`Sexy/src/ReconImageIds.cpp`, are not edited by hand. The generators are
missing from this repository.

**Reason.** A hand edit in a transcribed file is lost the next time the file
is transcribed. The generator is the only way to change those files
consistently.

**Open problem.** `tools/ida_transcribe.py` and `tools/gen-image-ids.py` are
not in this repository, nor in the upstream. Recovering them is on the
backlog: without them, those files cannot be regenerated.

## D9. The console content is the upstream's, and it is GPL

**Decision.** The twelve achievements, the house and records scene, the
leaderboard sign, the trash piles and the house blueprints live in files that
carry the `PvZ TV Touch Team` GPL header, and the upstream carries the same
files.

**Reason.** They come from the AndroidTV project, which is GPL. The upstream
took them in, so the sync keeps carrying them, and the notice file describes
the adaptation.

**Consequence.** Do not present them as a fork delta, and do not merge them
into MIT-only files without moving the header.

## D10. Assets are not in the repository

**Decision.** The game reads `assets/main.pak` and loose files from the
resource root, which is not in git. `setup.env` is read outside the
archives, before they are mounted.

**Reason.** The assets belong to PopCap / EA. The repository ships code and
build instructions, and the user supplies the resources.

**Consequence.** A change that needs an image that does not exist shows up
as a missing-resource error at run time, not as a compile error.

## D11. The enum tables live in `Sexy/include/ReconTypes.h`

**Decision.** `SEED_*`, `STORE_ITEM_*`, `REANIM_*`, `GAMEMODE_*` and the rest
are declared in the generated `ReconTypes.h`, and the port uses those names.

**Reason.** The tables come from the binary. A literal typed by hand in a
function rots the moment the table changes, and the tables do change between
builds.

## D12. The verification is the build plus the smoke test

**Decision.** There is no test suite, and none is planned. A change is
verified by building the platform that matters and running
`LawnTV.exe --frames 5 --screenshot smoke.png --headless`, then reading
`LawnTV-diagnostics.log`.

**Reason.** The project is a decompilation of a game with no testable API
surface. The smoke test is the closest thing to a test that the whole
pipeline (resources, renderer, widgets, input) still works.

**Consequence.** "It compiles" is not "it works", and neither is "it looks
right".

## D13. iOS ships as an unsigned `.ipa`

**Decision.** The CI assembles a plain `.app`, signs it ad hoc and zips it.
The user installs it with Sideloadly or AltStore.

**Reason.** The repository cannot hold the signing secrets, and the app
bundle is assembled by the workflow out of `ios/Info.plist`,
`ios/LaunchScreen.storyboard` and the app icon.
