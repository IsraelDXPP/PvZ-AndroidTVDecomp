# State

Where the project is. This file is the one to read first, and the one to
update when a round of work closes.

Last updated: 2026-10-21.

## What this is

A C++ decompilation of `libGameMain.so` (Plants vs. Zombies TV / Android
edition) with the console content restored and the platform layer replaced by
SDL3 and bgfx. The upstream decompilation is itself unfinished: many functions
remain approximate, and the README says so. The port builds, starts, loads
the resources, renders the title screen and runs.

## Done

- **Game logic ported** from the v115 build: `LawnApp`, `Board`, plants,
  zombies, levels, modes, dialogs, the `Sexy` framework and the `Tod*`
  helpers. Each ported function carries the address it came from.
- **Platform layer**: SDL3 for windows, input, gamepads, audio, files and
  threads; bgfx for rendering over D3D11/12, GL, Vulkan and Metal. The
  JNI entry point and the Win32 drivers are gone.
- **Console content**: the twelve achievements, the house and records scene,
  the underground achievements view, the leaderboard sign, the trash piles,
  the house blueprints and the store's house page. Conditions audited in
  `docs/achievement-conditions.md`. The upstream carries these files too.
- **Platforms**: Windows x64 and x86, macOS arm64 and x64, Linux x64 and
  arm64, Android arm64-v8a, armeabi-v7a and x86_64, iOS arm64.
- **CI**: `.github/workflows/build.yml` builds every platform; the iOS job
  assembles an unsigned `.ipa`.
- **Upstream sync**: `sync-upstream.yml` merges the upstream every six hours
  through a pull request.
- **Verification**: the build plus the headless smoke test. Measured on
  2026-10-21: `LawnTV.exe --frames 5 --screenshot smoke.png --headless`
  exits with code 0 and writes a 1280x720 PNG.
- **Resource loading fixed for the shipped resources.** `resources.xml` ships
  attributes with no value (`<Sound ... 3d />`), and `3d` is not a legal XML
  name; `menu-atlas.xml` has a stray `/` before `>`; `levels.xml` is cut
  before its last end tag. The strict XML reader rejected all three, so
  `LoadXmlText` now retries once through a tolerant pass that makes those
  shapes explicit: bare attributes get an empty value, a name that cannot
  start an XML name is prefixed with `_`, a stray slash becomes the
  self-closing marker, and whatever is still open at the end of the buffer is
  closed. The retry only runs when the strict parse failed, and a genuinely
  malformed file still fails with the original error.
- **Accented characters render.** `ImageFont::GetMappedChar` falls back from
  the Latin-1 supplement to the matching ASCII character, so a character
  that the bitmap font does not carry does not disappear from the screen.

## In progress

Nothing is in progress in the working tree. The last round of work (the
tolerant XML pass, the Latin-1 fallback and this documentation set) is
committed and the smoke test passes.

## Known gaps

- **The decompilation is unfinished.** The upstream says many functions are
  approximate; this port inherits that. The README repeats the warning.
- **The transcription generator is missing.** `tools/ida_transcribe.py` and
  `tools/gen-image-ids.py` are not in this repository, nor in the upstream.
  Forty-six sources and three headers are marked
  `Generated by tools/ida_transcribe.py. Do not edit.`, and
  `Sexy/src/ReconImageIds.cpp` is generated by `tools/gen-image-ids.py`.
  Until they are recovered, those files cannot be regenerated and a hand
  edit is lost the next time they are.
- **No test suite.** The verification is the build and the smoke test
  (`docs/verificacion.md`).
- **One banner disagrees with the symbol table**: `LawnApp::SaveFileExists`
  says 112 bytes at `0x2B33B8`; the v115 symbol table says 136. The table
  wins; the banner has not been corrected yet.
- **The local Hex-Rays exports are the wrong build.** Both exports on this
  machine are not v115 (`docs/binario.md`), so their addresses must not be
  used to fix the code.
- **The assets are not in the repository.** A missing image shows up as a
  run-time error, not a compile error.

## How to update this file

- After a round of work, update "Done", "In progress" and "Known gaps", and
  move the item in the backlog that was closed.
- Write the exact measurement, not the impression: the command that was run
  and what it printed. A claim without a command is a guess.
- Keep it short. Details belong in the file the item refers to.
